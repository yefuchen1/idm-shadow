改进
- BT 的同时在线 peer 上限从 100 提到 400。
  这个数是库内部写死的：只有它自己管的出站线程数调到了 200，
  但 peer 进 swarm 的准入判断用的是另一个写死的 100，
  所以之前不管怎么调连接数，实际在线 peer 都卡在 100。
- 下载和更新检查现在会走 Windows 的系统代理设置了。
  以前程序是直连的：浏览器能打开的网址、别的工具能下的文件，
  在程序里却下不下来。开着 Clash 之类的代理时尤其明显。
- 磁力链接支持 base64 编码的 info hash 了。
  以前只认十六进制和 base32 两种写法，遇到 base64 的链接
  会直接报「Invalid info hash format」，一个字节都下不动。
- 修了一个会让 BT 下载彻底卡死的缺陷：
  别人连过来的连接断掉时，我们没有把它占着的块还回去。
  那些块就永远不会再被任何人要——一个块 16 KB，
  积少成多整个下载就停摆了，而且不会报错，只是不动了。

注意
- 下载目录里如果有上次没下完的半截文件，下载可能会停住不动。
  这是下载库自身的行为（已存在的文件不会被重新分配大小），
  删掉残留文件重新下就能恢复。
- 这次的改动不涉及做种上传，也依然没有加 uTP / WebRTC 那条线路。
- 迅雷那种几百上千的连接点，靠的是它自己的私有节点和协议，
  这里的公开 tracker + DHT 规模比不了。
