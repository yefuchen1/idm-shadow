修复
- 磁力链接卡住不动时不再一直空转占 CPU。
  以前遇到没人做的种子，任务会永远停在"下载中"，
  速度一直是 0 但 CPU 一直烧着，界面上的进度条也不动。
  现在会先踢掉当前这批连接、重新去找 peer 换一批试试；
  换了三批还是没有任何进展，才会判定种子确实失效，
  把任务标成失败——已经下好的部分会保留，
  换个种子源或者点"重试"就能接着下。
- 磁力链接不再往硬盘上写没完没了的调试日志。
  以前每个任务都会在程序目录旁生成一个 `debug.log`，
  半小时能涨到 7MB 多，全是重复的连接记录。
  现在这个文件不会再生成，需要排查时用环境变量 `RUST_LOG=debug` 启动即可看到。
- DHT 候选节点不再无限堆积。
  以前网络来的节点会一直攒着，每 30 秒又全部重新问一遍，
  节点一多就是几百次域名解析和发包。
  现在只保留最近的节点，分批询问。
- BT 下载的进度上报不再重复刷屏。
  内容没变化的进度不再重复写数据库和通知界面。
- 等待"选择要下载的文件"时不再反复查数据库。
  以前每 200 毫秒查一次，你放着不选它就一直查；
  现在选好之后立刻就有反应。

改进
- 磁力链接没有进展时轮询变慢，有进展时保持跟手，
  空闲时基本不占 CPU。
- BT 分片的"稀缺度"改为定时刷新，不再每轮都重算。

说明
- 本次更新只涉及桌面程序本身，不包含浏览器扩展改动，
  不需要重新加载扩展。
